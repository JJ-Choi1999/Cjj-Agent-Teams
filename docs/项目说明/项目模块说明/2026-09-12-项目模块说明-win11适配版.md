## 一、阅读指南

1. 母文档描述的 21 个模块（M01–M21）与相对路径在 Windows 11 上**全部存在且语义一致**，差异集中在**宿主工具链、Shell 语义、路径映射、换行符与执行位**四类。
2. Windows 11 **不是**"不能开发"，而是"**必须借助 WSL 2 / Git Bash 才能跑 bash 与 GNU make**"。仓库中约 90% 的脚本（`Makefile` 全部 recipe、`install/*.sh`、`shared/lib/*.sh`、`hack/*.sh`、`tests/*.sh`）是 Bash + GNU coreutils 语义。
3. 官方 Windows 路径已经存在且是第一等公民：
   - `install/agentteams-install.ps1`（PowerShell 7+ 安装器）
   - `install/agentteams-import.ps1`（资源导入）
   - `tests/check-windows-appservice-normalization.ps1`、`tests/check-powershell-deepseek-harness-latest.ps1`
   - `docs/usage/deployment/windows.md`（官方 Windows 部署指南，含截图）
4. 与 `docs/.../windows.md` 的关系：官方文档面向**最终用户装完即用**；本文档面向**开发者/维护者**，补充母文档模块视角的适配细节。

## 二、开发环境配置（Windows 11）

### 2.1 宿主基线（官方要求 + 实操建议）

| 项 | 官方要求（见 `docs/usage/deployment/windows.md`、`install/README.md`） | Windows 11 实操建议 |
|---|---|---|
| 操作系统 | Windows 10 1903+ / Windows 11；**不支持在虚拟机内运行**（VM 无法跑 Linux 容器） | Win11 22H2+，启用 WSL 2 |
| 容器运行时 | Docker Desktop 4.20+（WSL 2 后端）；`podman` 亦被脚本探测 | Docker Desktop + WSL 2 后端；Settings → General 勾选 WSL 集成 |
| PowerShell | 7.0+（系统自带 5.1，脚本需要 7+） | `winget install Microsoft.PowerShell`，统一用 `pwsh` |
| WSL | 必须启用 | `wsl --install -d Ubuntu`；`wsl --set-default-version 2` |
| 内存 | 最低 4 GB，推荐 8 GB+ | `%USERPROFILE%\.wslconfig` 设 `memory=8GB`（官方 FAQ 亦如此建议），`wsl --shutdown` 后重启 Docker Desktop |
| 磁盘 | 最低 10 GB，推荐 20 GB+ | Rust 模块（M09）与多架构镜像会额外占用 10 GB+ |

### 2.2 Shell 与 make —— 本仓库在 Windows 上最大的适配点

`Makefile` 的 recipe 全部是 POSIX shell 语法，且包含 `VAR=val cmd` 前缀赋值、`rm -rf`、`cp -r`、`diff -r`、`grep -q`、`xargs -r`、`sort -V`、`$(shell ...)`：

```86:88:Makefile
# Named build context for shared libraries (requires BuildKit / Docker 23+)
SHARED_LIB_CTX = --build-context shared=./shared/lib
```
```255:255:Makefile
IS_PODMAN := $(shell docker version 2>&1 | grep -qi podman && echo 1 || echo 0)
```

因此：

- **不推荐**在 `cmd.exe` 下直接用 `mingw32-make`（默认 `SHELL=cmd`，`VAR=val cmd`、`rm -rf` 全部失败）。
- **推荐方案 A（首选）**：在 WSL 2 Ubuntu 内克隆/打开仓库，用 WSL 内原生 `make` + `bash`：

  ```bash
  cd /mnt/d/AiProject/Cjj-Agent-Teams      # 本机仓库的 WSL 路径
  make help
  ```

- **推荐方案 B**：Git for Windows（自带 Git Bash + GNU make 可选）+ `choco install make`，并在 `Makefile` 之外保证 `sh.exe` 在 PATH 首位；或在 PowerShell 中显式指定 `make SHELL="C:\Program Files\Git\bin\bash.exe" -e`。
  > 注意：`SHELL` 覆盖会让 `$(shell ...)` 与 recipe 都走 bash，这是让 Makefile 在 Windows 可用的关键。
- **方案 C（脚本级）**：单个脚本用 Git Bash 执行，例如 `& "C:\Program Files\Git\bin\bash.exe" ./install/agentteams-verify.sh`。

> **结论**：Windows 11 上的"标准开发姿势"是 **WSL 2 + Docker Desktop(WSL 集成)**；PowerShell 主要负责安装/导入（官方 `.ps1`），Bash 负责构建与测试。

### 2.3 Git 配置（防 CRLF 污染，必做）

仓库换行策略**只保护 Shell 脚本**，其余文件依赖宿主 Git 设置：

```1:3:.gitattributes
# Shell scripts must remain executable by Unix shells after Windows checkouts.
*.sh text eol=lf
deepseek-harness/scripts/agentteams-dsh text eol=lf
```

- `Makefile`、`Dockerfile*`、`helm/**/*.yaml`、`.github/workflows/*.yml` **未声明 `eol`**。
- 若 `core.autocrlf=true`（Windows 安装 Git 时常见默认），`Makefile` 会变成 CRLF → `make` 报 `missing separator`；`Dockerfile` 的续行 `\` 与 `RUN` 也会出问题。

**必须执行**：

```powershell
git config --global core.autocrlf input   # 或 false；不要用 true
git config --global core.eol lf
# 已污染的本地副本（工作区无改动时）重建：
git rm --cached -r . ; git reset --hard
```

或仅对本仓库设置：`git config core.autocrlf input`（去掉 `--global`）。

### 2.4 执行位（+x）

- NTFS 不保存 Unix 可执行位；Git 在 Windows 检出后脚本"不可执行"是正常的，用 `bash script.sh` 调用即可。
- 在 WSL 中访问 `/mnt/d/...`（drvfs）时，文件默认**全部表现为可执行**（777 风格），因此直接 `./install/agentteams-install.sh` 通常也能跑；但换行符必须是 LF（见 2.3）。
- **不要在 Windows 侧校验/提交文件模式**：保持 `core.fileMode=false`（Windows 默认），避免把整个仓库误标为 chmod 变更。

### 2.5 Docker Desktop(WSL 2) 关键设置

| 设置项 | 建议值 | 原因 |
|---|---|---|
| Use the WSL 2 based engine | 开启 | `install/README.md` 明确要求；否则 Linux 容器不可用 |
| Resources → WSL integration | 勾选你的发行版 | WSL 内可直接用 `docker` / `make` |
| Docker Engine 镜像加速 | 国内网络时配置 registry-mirror | `docs/usage/deployment/windows.md` FAQ「镜像拉取超时」 |
| File sharing | 无需额外配置（WSL 后端自动共享 `/mnt/*`） | 卷挂载路径见第四章 |
| 代理（如需要） | 构建代理用 `host.docker.internal` | 见第五章 5.2 |

### 3.2 与 macOS/Linux 的差异摘要

| 维度 | Linux | macOS | **Windows 11** |

## 四、路径处理

### 4.1 宿主路径 → 容器路径：PowerShell 安装器的转换规则

Windows 安装器内置路径转换函数，这是 Windows 与 macOS 最本质的差异：

```773:789:install/agentteams-install.ps1
function ConvertTo-DockerPath {
    param([string]$Path)

    # Convert Windows path to Docker mount format
    $fullPath = (Resolve-Path $Path -ErrorAction SilentlyContinue).Path
    if (-not $fullPath) {
        $fullPath = $Path
    }

    # Convert C:\path to /c/path format for Docker
    if ($fullPath -match "^([A-Za-z]):") {
        $drive = $Matches[1].ToLower()
        $rest = $fullPath.Substring(2).Replace("\", "/")
        return "/$drive$rest"
    }
    return $fullPath.Replace("\", "/")
}
```

| 宿主真实路径 | 传给 Docker 的形式 | 说明 |
|---|---|---|
| `C:\Users\you\agentteams-manager` | `/c/Users/you/agentteams-manager` | 驱动器小写 + 反斜杠转正斜杠 |
| `D:\AiProject\Cjj-Agent-Teams` | `/d/AiProject/Cjj-Agent-Teams` | 本机仓库（非 `C:` 盘同样规则） |
| WSL 视角同一路径 | `/mnt/d/AiProject/Cjj-Agent-Teams` | 在 WSL 内执行时用这个形式 |

> **重要**：在 PowerShell 手工 `docker run` 时**不要**直接写 `-v C:\path:/container`（冒号与反斜杠易被解析）；用 `-v "D:/path:/container/path"` 或 `-v "/d/path:/container/path"`。

### 4.2 Docker socket 的 Windows 特有写法

```2861:2861:install/agentteams-install.ps1
                    -v "//var/run/docker.sock:/var/run/docker.sock" `
```
```3260:3261:install/agentteams-install.ps1
        $ctrlArgs += @("-v", "//var/run/docker.sock:/var/run/docker.sock")
        $ctrlArgs += @("--security-opt", "label=disable")
```

- Windows 上必须写 **`//var/run/docker.sock`**（前导双斜杠），原因：Docker Desktop 实际暴露的是命名管道 `//./pipe/docker_engine`，而单斜杠 `/var/run/docker.sock` 会被 PowerShell/MSYS 当作路径改写。
- 对比：Bash 安装器（macOS/Linux）走的是 `install/agentteams-install.sh` 中的探测逻辑，依次尝试 `$XDG_RUNTIME_DIR/docker.sock` → `$HOME/.docker/run/docker.sock` → `/var/run/docker.sock`，**与 Windows 完全不同**。
- `--security-opt label=disable` 在 Windows/macOS 上是无害空操作（为 Podman/SELinux 准备），保留即可。

### 4.3 默认挂载清单（Windows 11 视角）

| 宿主（Windows） | 容器内 | 触发位置 | 适配要点 |
|---|---|---|---|
| `%USERPROFILE%\agentteams-manager` | `/root/manager-workspace` | `install/agentteams-install.ps1` | 默认值是 `%USERPROFILE%`，与 macOS 的 `$HOME` 语义一致但书写不同 |
| `%USERPROFILE%`（可由 `AGENTTEAMS_HOST_SHARE_DIR` 改） | `/host-share` | 同上 | **默认共享整个用户目录**，Windows 用户目录含 `.ssh`、浏览器配置等，建议改小范围 |
| `//var/run/docker.sock` | `/var/run/docker.sock` | 同上 | 见 4.2 |
| 命名卷 `agentteams-data` | `/data` | 同上 | 命名卷与平台无关，**推荐**（优于 bind mount） |

容器内启动脚本依赖固定 Linux 路径，**不要试图改成 Windows 路径**：

```8:9:manager/scripts/setup-host-symlinks.sh

gitconfig_container="/root/.gitconfig"
```
```17:17:shared/lib/agentteams-env.sh

```

Windows 上要让 `/host-share/.gitconfig` 存在，确保宿主有 `C:\Users\<你>\.gitconfig`（`git config --global user.name/user.email` 会生成）。

### 4.4 大小写、长路径与文件锁

| 风险 | 表现 | 适配 |
|---|---|---|
| 大小写不敏感 | Windows 上把 `docs/zh-cn` 写成 `docs/zh-CN` 不报错，但 Linux 容器 / CI 找不到 | 改名必须两步：`git mv a b.tmp` → `git mv b.tmp b` |
| 长路径（MAX_PATH 260） | `openclaw-base`/`openhuman` 构建上下文、`node_modules`、`target/` 深目录 → IDE 索引/打包失败 | 开启 `LongPathsEnabled=1`（`gpedit` 或注册表），仓库根目录尽量短（如 `D:\src\AgentTeams`） |
| Windows Defender 实时扫描 | `docker build` 上下文打包、`node_modules` 频繁读写极慢 | 排除仓库目录与 `%LOCALAPPDATA%\Docker\wsl` |
| 仓库位于 `D:\` + Docker Desktop | 构建上下文经 WSL `/mnt/d` 读取，吞吐低于 Linux 文件系统 | 大构建建议在 WSL 家目录内克隆一份副本 |
| 文件被 IDE/编辑器占用 | `Makefile` 的 `rm -rf ./agentteams-controller/agent` 临时目录清理可能失败 | 构建时关闭对该临时目录的索引 |

### 4.5 PowerShell 路径 API 对照（写脚本时用）

## 五、构建注意事项

### 5.1 环境变量语法：PowerShell ≠ Bash

| 场景 | Bash（WSL/Git Bash） | PowerShell 7 |
|---|---|---|
| 临时环境变量 | `AGENTTEAMS_LLM_API_KEY=sk-x make install` | `$env:AGENTTEAMS_LLM_API_KEY="sk-x"; .\install\agentteams-install.ps1 manager` |
| 非交互安装 | `AGENTTEAMS_NON_INTERACTIVE=1 bash install/agentteams-install.sh` | `$env:AGENTTEAMS_NON_INTERACTIVE="1"; .\install\agentteams-install.ps1` |
| 持久化 | `export X=1`（当前会话） | `[Environment]::SetEnvironmentVariable("X","1","User")` |
| 传 build-arg | `make build DOCKER_BUILD_ARGS="--build-arg ..."` | 在 bash 中执行同样的命令（PowerShell 需 `--%` 或转义，不推荐） |

> **`make` 的目标只在 bash 下安全**：`make install` / `make test` 依赖 `VAR=val cmd`、`bash ./install/agentteams-install.sh`（见 `Makefile:649-657`、`Makefile:780-786`）。请统一在 WSL/Git Bash 中执行。

### 5.2 代理与镜像源（国内网络必备）

- Docker build **不会继承宿主代理**。Windows 上用 `host.docker.internal`（Docker Desktop 会解析到宿主）：

  ```bash
  make build-manager DOCKER_BUILD_ARGS="--build-arg http_proxy=http://host.docker.internal:1087 --build-arg https_proxy=http://host.docker.internal:1087"
  ```

  > 不要写 `127.0.0.1:1087`：在构建容器里它指向构建容器自身。

- 无代理时用国内镜像参数（`openclaw-base` 用 NPM 源，Python 镜像用 PIP 源）：

  ```bash
  make build-openclaw-base DOCKER_BUILD_ARGS="--build-arg APT_MIRROR=mirrors.aliyun.com --build-arg NPM_REGISTRY=https://registry.npmmirror.com/"
  ```

- 本地构建 `openclaw-base` 后的**成对参数**（Windows 上极易踩坑，因为默认会拉远端镜像）：

  ```bash
  make build-manager build-worker \
      OPENCLAW_BASE_IMAGE=agentteams/openclaw-base \
      OPENCLAW_BASE_VERSION=latest
  ```

### 5.3 BuildKit / 命名构建上下文

`Makefile` 大量使用命名上下文，需要 BuildKit（Docker Desktop 默认开启，需 Docker 23+）：

```88:91:Makefile
SHARED_LIB_CTX = --build-context shared=./shared/lib

# Named build context for local copaw_worker extension
COPAW_WORKER_CTX = --build-context copaw-worker=./copaw
```

- Windows 上若报 `unknown flag: --build-context`，说明客户端过旧或 `DOCKER_BUILDKIT=0`；恢复 `$env:DOCKER_BUILDKIT="1"`。
- 命名上下文的路径 `./shared/lib` 由 make 以 POSIX 风格传入，**必须**在 bash 下执行。

### 5.4 多架构与平台

| 目标 | 命令 | Windows 11 适配 |
|---|---|---|
| 本地开发构建（宿主架构） | `make build` | Win11 通常 amd64 → `linux/amd64` |
| 指定平台 | `make build DOCKER_PLATFORM=linux/amd64` | 需要 buildx（`make buildx-setup`） |
| 多架构推送 | `make push` | 走 `docker buildx create --driver docker-container`，需 WSL 2 后端支持 QEMU |
| 检测 Podman | `IS_PODMAN := $(shell docker version ...)` | 若装了 Podman Desktop，`make push` 会切到 `podman manifest` 分支 |

- Windows 上 buildx 的 `docker-container` 驱动在 WSL 2 后端下可用；**`docker` 上下文必须指向 `desktop-linux`**（`docker context ls` 确认）。
- 首次 `make push` 会创建 builder `agentteams-multiarch` 并 bootstrap，Windows + 企业代理下可能卡在拉取 buildkit 镜像 → 给 Docker Desktop 配代理。

### 5.5 各镜像构建的 Windows 提示

| 目标 | 命令 | Windows 提示 |
|---|---|---|
| `openclaw-base` | `make build-openclaw-base` | clone + `npm` 构建，耗时最长；务必配 NPM 源或代理 |

### 6.2 一键安装（PowerShell 路径）


Windows 专属产物位置：

| 内容 | 路径 |
|---|---|
| 安装配置（含密码） | `%USERPROFILE%\agentteams-manager.env` |
| 安装日志 | `%USERPROFILE%\agentteams-install.log` |
| Manager 工作区 | `%USERPROFILE%\agentteams-manager\` |
| 数据 | Docker 命名卷 `agentteams-data` |

### 6.3 Windows 特有的部署差异

1. **Dashboard 不支持 PowerShell 安装器**。`local.md` §13 与 `Makefile` 注释均明确：Dashboard 仅 Bash 安装器提供（`make install-dashboard` / `AGENTTEAMS_DASHBOARD=1`）。Windows 上如需 Dashboard，请在 WSL 内执行 Bash 安装器。
2. **端口与域名**：默认域名 `*-local.agentteams.io` 会自动解析到 `127.0.0.1`；Windows 上排查端口占用用：

   ```powershell
   netstat -ano | findstr "18088"
   Get-NetTCPConnection -LocalPort 18088 -ErrorAction SilentlyContinue
   ```

3. **"允许外部访问"**（`AGENTTEAMS_LOCAL_ONLY=0`）时 Windows 防火墙会弹窗；局域网访问用 `ipconfig` 查 IPv4，并在防火墙放行 18080/18001/18088。
4. **WSL 2 内存不足**是最常见的"Manager Agent 启动超时"原因（官方 FAQ）：编辑 `%USERPROFILE%\.wslconfig` → `[wsl2] memory=8GB` → `wsl --shutdown` → 重启 Docker Desktop。
5. **容器日志查看**（Windows 下等价命令）：

   ```powershell
   docker logs agentteams-controller
   docker logs agentteams-manager
   docker exec agentteams-manager cat /var/log/agentteams/manager-agent.log
   ```

   注意 `docker exec` 内部的路径仍是 **Linux 路径**（`/var/log/...`），不要写 Windows 路径。
6. **卸载**：PowerShell 安装器会移除容器、卷、env 文件；但 `%USERPROFILE%\agentteams-manager` 工作区可能保留，需手工删除（官方 Windows 文档已提示）。
7. **资源导入**：`.\install\agentteams-import.ps1` 会把本地文件 `docker cp` 进容器再调用 `agt`；ZIP 路径含中文/空格时请加引号，脚本已用 `Split-Path -Leaf` 处理文件名。

### 6.4 本地 K8s（kind）在 Windows 上

`hack/local-k8s-up.sh` 是 Bash 脚本，且使用 `uname -m` 推导平台、`docker save | docker exec ctr` 导入镜像：

```153:153:hack/local-k8s-up.sh
    PLATFORM="linux/$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/')"
```

因此在 Windows 11 上：

1. 必须在 **WSL 内**执行 `AGENTTEAMS_LLM_API_KEY=sk-xxx bash hack/local-k8s-up.sh`（或 `make local-k8s-up`）。
2. kind 需要 Docker Desktop 运行且 WSL 集成开启；`hack/kind-config.yaml` 把 `30080 → 宿主 18080`，请先确认 18080 空闲。
3. `kind load docker-image` 在 Windows + WSL 上会经 `docker save` 传输大镜像，较慢但可用。
4. Helm chart 需要 `helm dependency build` 拉取 Higress 子 chart，需网络/代理。

| `Makefile:NN: *** missing separator. Stop.` | 换行被转成 CRLF | 2.3 的 Git 配置 + 重建工作区 |
| `'rm' is not recognized` / `cp: command not found` | 在 cmd/PowerShell 下跑 make | 改在 WSL/Git Bash 执行 |
| `unknown flag: --build-context` | BuildKit 未启用 | `$env:DOCKER_BUILDKIT="1"` 或升级 Docker |
| 卷挂载后容器内看不到文件 | 传了 `C:\...` 或单斜杠 socket | 用 `ConvertTo-DockerPath` 规则（4.1）与 `//var/run/docker.sock`（4.2） |
| 构建容器内访问代理失败 | 用了 `127.0.0.1` | 改用 `host.docker.internal` |
| Manager 长时间未就绪 | WSL 2 内存不足 | `%USERPROFILE%\.wslconfig` → `memory=8GB` |
| 端口被占用 | 18080/18001/18088 冲突 | `netstat -ano \| findstr 18088`，改用 Manual Setup 换端口 |
| `docs/zh-cn` 文件在 CI 找不到 | 大小写改名未生效 | 用 `git mv` 两步改名 |
| 脚本语法错误 `\r` | `.sh` 被写成 CRLF | `.gitattributes` 已强制 LF，重新检出；编辑器的 autocrlf 也要关 |
| Dashboard 装不上 | PowerShell 安装器不支持 | 在 WSL 内用 Bash 安装器 + `make install-dashboard` |

### 8.3 最小可用 Windows 11 开发闭环

```powershell
# 1) 宿主配置（一次性）
wsl --install -d Ubuntu
git config --global core.autocrlf input
winget install Microsoft.PowerShell Docker.DockerDesktop
#   编辑 %USERPROFILE%\.wslconfig 设 memory=8GB，重启 Docker Desktop

# 2) WSL 内（开发/构建/测试主战场）
cd /mnt/d/AiProject/Cjj-Agent-Teams
make help
make build-manager build-worker \
     OPENCLAW_BASE_IMAGE=agentteams/openclaw-base OPENCLAW_BASE_VERSION=latest
AGENTTEAMS_LLM_API_KEY=sk-xxx make install

# 3) PowerShell 内（面向最终用户的安装/导入）
$env:AGENTTEAMS_LLM_API_KEY="sk-xxx"
.\install\agentteams-install.ps1 manager
```
