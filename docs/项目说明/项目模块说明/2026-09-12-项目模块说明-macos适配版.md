## 一、阅读指南

1. macOS 是 AgentTeams 的**一等支持平台**：官方 `docs/usage/deployment/local.md` 正文即"single macOS or Linux host"，`install/agentteams-install.sh` 已针对 macOS 做了专门适配（bash 3.2 兼容、Apple Silicon JVM 修复、Podman 分支）。
2. 与 Windows 11 相比，macOS 的优势是 **POSIX 工具链原生可用、执行位保留、换行默认 LF**；劣势是 **BSD userland 与 GNU coreutils 的差异** 以及 **Apple Silicon 的架构/虚拟化开销**。
3. 需要特别留意的三个"macOS 专属陷阱"：
   - 系统自带 **bash 3.2**（安装器已兼容，但 `migrate/skill/scripts/analyze.sh` 等脚本不兼容）；
   - BSD 版 `xargs -r` / `date -d` / `sort -V` **不存在**，而仓库多处使用；
   - **Apple Silicon 上 Higress Console 需要 JVM 参数修复**（安装器会自动加，手工 `docker run` 时需自己加）。
4. 官方文档分工：`docs/usage/deployment/local.md`（macOS/Linux）、`docs/usage/deployment/windows.md`（Windows）、`docs/usage/deployment/kubernetes.md`（K8s）。本文档站在母文档模块视角补充适配细节。

## 二、开发环境配置（macOS）

### 2.1 宿主基线

| 项 | 要求 / 建议 | 说明 |
|---|---|---|
| macOS 版本 | 12 Monterey 及以上 | Swift/容器工具链依赖较新系统 |
| CPU 架构 | Intel x86_64 或 Apple Silicon arm64 | 官方 local.md：`Supports both Intel (amd64) and Apple Silicon (arm64)` |
| 容器运行时 | **Docker Desktop 推荐**；Podman 亦可（`local.md` §Supported platforms） | 需能执行 `docker ps` / `podman ps` |
| Shell | 默认 zsh（登录 shell），脚本用 `bash` 调用 | 见 2.2 |
| 资源 | 最低 2 核 / 4 GB / 10 GB；推荐 4 核+ / 8 GB+ / 20 GB+ | 多 Worker 或 OpenClaw 运行时需更多 |
| 网络 | 能拉取镜像并访问模型服务 | 容器访问宿主见 4.3 |
| Xcode CLT | 建议安装 `xcode-select --install` | Go `CGO_ENABLED=1`（M01）需要 clang |

### 2.2 Shell：bash 3.2 的现实与边界

`install/agentteams-install.sh` 明确声明兼容系统自带 bash：

```264:266:install/agentteams-install.sh
# Centralized message dictionary and msg() function
# Compatible with bash 3.2+ (macOS default) — uses case instead of declare -A
# ============================================================
```

| 脚本 | macOS 自带 `/bin/bash` 3.2 能否直接跑 | 说明 |
|---|---|---|
| `install/agentteams-install.sh` | ✅ 可以 | 作者显式规避了 `declare -A` |
| `Makefile` 的 recipe | ✅ 可以（只要 `make` 存在） | recipe 只用 POSIX sh 语法 |
| `shared/lib/*.sh`、`shared/tests/*.sh` | ✅ 基本可以 | 未使用 bash 4 特性 |
| `migrate/skill/scripts/analyze.sh` | ❌ **不可以** | 使用 `declare -A CMD_SOURCES`（关联数组，需 bash 4+） |
| 部分 `tests/lib/*.sh` | ⚠️ 需 GNU 工具（见 3.2） | 不是 bash 版本问题，而是 coreutils 差异 |

**适配动作**：

```bash
# 方案 A（推荐）：安装 bash 5 并显式使用
brew install bash
/opt/homebrew/bin/bash migrate/skill/scripts/analyze.sh     # Apple Silicon
/usr/local/bin/bash migrate/skill/scripts/analyze.sh        # Intel

# 方案 B：在容器/CI 内执行需要 bash 4+ 的脚本
#   （CI 全部 runs-on: ubuntu-latest，最接近真实运行环境）
```

> zsh 作为默认 shell 不影响脚本执行（`bash script.sh` 会启动 bash），但**不要**用 `sh script.sh` 跑仓库脚本——`sh` 在 macOS 上是 bash 的 POSIX 模式，`local`、数组、`[[ ]]` 等行为会变化。

### 2.3 GNU 工具缺失：macOS 最主要的适配点

仓库多处使用 GNU 专属参数，macOS 的 BSD 版本会直接报错：

| 位置 | 用法 | macOS 表现 | 适配 |
|---|---|---|---|
| `Makefile:831`（`clean` 目标） | `xargs -r docker rm -f` | BSD `xargs` 无 `-r` → 报 `illegal option` | 见下方"通用修法" |
| `tests/lib/agent-metrics.sh:546` | `date -d "${ts}" +%s` | BSD `date` 无 `-d` | 同上（需 `gdate`） |
| `install/agentteams-install.sh:87` | `sort -V` 比较版本 | BSD `sort` 不支持 `-V` | 同上（需 `gsort`） |
| 宿主脚本中的 `sed -i` | BSD `sed -i` 需要 `-i ''` | 语法不同 | 仓库内 `sed -i` 仅出现在**容器内**脚本（如 `manager/scripts/init/start-element-web.sh`），宿主脚本未使用；自写脚本时注意 |
| `find -print0` / `stat -c` 等 | GNU 习惯 | BSD 对应 `stat -f` | 自写脚本时注意 |

**通用修法（推荐，一次到位）**：

```bash
brew install coreutils findutils gnu-sed gnu-tar
# 把 GNU 版本前置到 PATH（Apple Silicon）
export PATH="/opt/homebrew/opt/coreutils/libexec/gnubin:/opt/homebrew/opt/findutils/libexec/gnubin:/opt/homebrew/opt/gnu-sed/libexec/gnubin:$PATH"
# Intel Mac 前缀为 /usr/local/opt/...
```

之后 `xargs -r`、`date -d`、`sort -V`、`sed -i` 均按 GNU 语义工作（`date`/`sort` 由 gnubin 提供别名，或使用 `gdate`/`gsort`/`gxargs`）。

> **重要**：`docs/usage/deployment/local.md` 建议用 `lsof -nP -iTCP:18080 -sTCP:LISTEN` 检查端口——`lsof` 在 macOS 上原生可用，**不需要** GNU 版本。

### 2.4 Git 与文件模式配置

- macOS 是**大小写不敏感但保留大小写**的 APFS（默认）：与 Windows 类似，误改大小写不会报错，但 Linux 容器/CI 会找不到文件。改名用两步：

  ```bash
  git mv docs/zh-cn docs/zh-cn.tmp && git mv docs/zh-cn.tmp docs/zh-cn
  ```

- 换行：macOS 检出为 LF，无需要额外配置；不建议开启 `core.autocrlf=true`。
- 执行位：`chmod +x` 在 APFS 上有效，`install/*.sh`、`hack/*.sh`、`shared/lib/*.sh` 直接 `./x.sh` 可运行（仓库 `.gitattributes` 也为此保障 LF）。

### 2.5 Docker Desktop / Podman 配置要点

| 设置项 | 建议 | 原因 |
|---|---|---|
| File sharing | 至少共享仓库所在目录与 `$HOME` | 默认 `AGENTTEAMS_HOST_SHARE_DIR=$HOME` 会挂载家目录 |
| VirtioFS | **启用**（Docker Desktop → Settings → General / Advanced） | 显著提升 bind mount 性能；旧 gRPC-FUSE 下 MinIO/构建会很慢 |
| Resources | 4 CPU / 8 GB 起 | 官方推荐值 |
| 磁盘镜像 | ≥ 40 GB | 多镜像 + Rust 构建（M09）+ 多架构 QEMU |
| 代理（如需要） | 设置 Docker Desktop 代理；构建传 `host.docker.internal` | 见 5.2 |
| Podman | `podman machine init && podman machine start` | Podman 无 systemd → 安装器的 `Podman autostart` 选项不出现（`local.md` §17） |

**Apple Silicon 专属**：Higress Console 在 arm64 上会因 JVM 指令集触发 SIGILL，安装脚本已自动兜底：

```3505:3509:install/agentteams-install.sh
    # Detect Apple Silicon (M1/M2/M3/M4) - need JVM fix for Higress Console
    # See: https://github.com/agentscope-ai/AgentTeams/issues/249
    if [ -z "${JVM_ARGS:-}" ] && [ "$(uname -m)" = "arm64" ] && [ "$(uname -s)" = "Darwin" ]; then
        log "Apple Silicon detected - setting JVM_ARGS to fix Higress Console SIGILL issue"
        JVM_ARGS="-XX:+UnlockDiagnosticVMOptions -XX:-UseAESCTRIntrinsics -XX:UseSVE=0"
    fi
```

因此**走官方安装脚本无需干预**；但若是手工 `docker run` Higress/embedded 容器，需自行传入：

```bash
-e JVM_ARGS="-XX:+UnlockDiagnosticVMOptions -XX:-UseAESCTRIntrinsics -XX:UseSVE=0"
```

### 3.2 与 Windows/Linux 的差异摘要

| 维度 | Linux | **macOS** | Windows 11 |
|---|---|---|---|
| Shell | bash 5 | 系统 bash 3.2（安装器已兼容；个别脚本需 bash 4+） | 需 WSL/Git Bash |
| GNU coreutils | 完整 | **BSD 变体，缺失 `xargs -r`/`date -d`/`sort -V`** | 缺失 → WSL/Git Bash |
| make | GNU make | GNU make 3.81（system） | 无 |
| 执行位 | 支持 | 支持 | 不支持 |
| 换行 | LF | LF | 默认可能 CRLF |
| 容器 socket | `/var/run/docker.sock`（含 rootless 变体） | `/var/run/docker.sock`（Docker Desktop）；Podman 由 VM 提供同路径符号链接 | `//var/run/docker.sock` |
| 访问宿主 | 宿主 IP / `host-gateway` | `host.docker.internal`（Docker Desktop）；Podman 用 **`host.containers.internal`** | `host.docker.internal` |
| 架构 | amd64/arm64 原生 | Apple Silicon = arm64（多架构需 QEMU） | 通常 amd64 |
| bind mount 性能 | 原生 | 较差（建议 VirtioFS + 命名卷） | 较差（WSL2 `/mnt/*`） |

## 四、路径处理

### 4.1 宿主路径 → 容器路径

macOS 与 Linux 同为 POSIX 路径，**无需任何转换函数**（这点与 Windows 的 `ConvertTo-DockerPath` 形成鲜明对比）：

| 宿主真实路径 | 传给 Docker 的形式 | 说明 |
|---|---|---|
| `/Users/you/agentteams-manager` | `/Users/you/agentteams-manager` | 原样传递 |
| `/Users/you/.agentteams/...` | 同上 | 无驱动器/反斜杠问题 |

官方默认值与 macOS 习惯一致：

| 变量 | macOS 默认值 | 容器内目标 |
|---|---|---|
| `AGENTTEAMS_WORKSPACE_DIR` | `${HOME}/agentteams-manager` | `/root/manager-workspace` |
| `AGENTTEAMS_HOST_SHARE_DIR` | `${HOME}` | `/host-share` |
| `AGENTTEAMS_DATA_DIR` | 命名卷 `agentteams-data` | `/data` |
| `AGENTTEAMS_ENV_FILE` | `${HOME}/agentteams-manager.env` | —— |
| 安装日志 | `${HOME}/agentteams-install.log` | —— |

> 对照 Windows：`%USERPROFILE%\agentteams-manager` 与 `/c/Users/...`。macOS 侧统一是 `/Users/<you>/...`。

### 4.2 Docker socket 探测顺序（macOS 与 Windows 完全不同）

macOS/Linux 走 Bash 安装器的多路径探测：

```1611:1627:install/agentteams-install.sh
            # Rootless Docker
            if [ -n "${XDG_RUNTIME_DIR:-}" ] && [ -S "${XDG_RUNTIME_DIR}/docker.sock" ]; then
                echo "${XDG_RUNTIME_DIR}/docker.sock"
                return 0
            fi

            # Rootless Docker (macOS fallback)
            if [ -S "${HOME}/.docker/run/docker.sock" ]; then
                echo "${HOME}/.docker/run/docker.sock"
                return 0
            fi

            # Root Docker
            if [ -S "/var/run/docker.sock" ]; then
                echo "/var/run/docker.sock"
                return 0
            fi
```

对照官方开发文档的映射表：

| 运行时 | 宿主 socket 路径 | 挂载命令 |
|---|---|---|
| Docker Desktop（macOS） | `/var/run/docker.sock` | `-v /var/run/docker.sock:/var/run/docker.sock` |
| Podman（macOS machine） | VM 内 `/run/podman/podman.sock`，VM 在 `/var/run/docker.sock` 提供符号链接 | `-v /run/podman/podman.sock:/var/run/docker.sock --security-opt label=disable` |
| Rootless Docker（macOS fallback） | `$HOME/.docker/run/docker.sock` | 同上（脚本自动命中） |

（来源：`docs/usage/development.md` §Container Runtime Socket）

> **macOS 无需** `//` 前缀；`--security-opt label=disable` 在 macOS 上是无害空操作。

### 4.3 容器访问宿主：`host.docker.internal` vs `host.containers.internal`

```142:142:AGENTS.md
Note: use `host.containers.internal` for Podman on macOS, `host.docker.internal` for Docker Desktop.
```

| 场景 | 正确写法 | 错误写法 |
|---|---|---|
| Docker Desktop（macOS）→ 宿主服务/代理/本地模型 | `http://host.docker.internal:PORT/...` | `http://localhost:PORT`（指向容器自身） |
| Podman machine（macOS）→ 宿主服务 | `http://host.containers.internal:PORT/...` | `host.docker.internal` 可能不可用 |

官方 FAQ 亦有同义说明：

```500:503:docs/usage/troubleshooting/faq.md
that the AgentTeams containers can reach. From inside Docker, `localhost` means the
container itself, not your Mac or host machine. Use a reachable host address,
for example `http://host.docker.internal:<port>/v1` on Docker Desktop, or the
host LAN IP on Linux/Podman when `host.docker.internal` is not available.
```

此外 controller 为本地后端容器注入 `host.docker.internal:host-gateway`：

```41:44:agentteams-controller/internal/controller/member_reconcile.go
const (
	runtimeRemoteManagedLocal        = "remote-managed-local"
	dockerHostInternalExtraHost      = "host.docker.internal:host-gateway"
	sandboxSetTokenRetryAfter        = 30 * time.Second
	sandboxSetTokenRefreshJitterMax  = 60 * time.Second
```

Docker Desktop（macOS）对该 extra-host 已内置处理；在 Podman/原生 Linux 上若解析失败，需改用 `host.containers.internal` 或宿主局域网 IP。

### 4.4 家目录共享的安全与性能提示

默认 `AGENTTEAMS_HOST_SHARE_DIR=$HOME`，会把整个用户家目录挂到容器 `/host-share`。macOS 家目录包含 `~/Library`、`~/.ssh`、钥匙串相关文件等敏感内容：

- 官方明确建议缩小范围：

  ```280:280:docs/usage/deployment/local.md
  Do not place the workspace in a temporary directory. Keep the host shared directory as narrow as possible so unnecessary credentials and personal files are not exposed to the agent runtime.
  ```

- **适配动作**：安装时把 Host shared directory 改为专用目录，例如：

  ```bash
  export AGENTTEAMS_HOST_SHARE_DIR="$HOME/agentteams-share"
  mkdir -p "$AGENTTEAMS_HOST_SHARE_DIR"
  ```

- Docker Desktop 首次挂载 `~/Desktop`、`~/Documents`、`~/Downloads` 等目录时 macOS 会弹"隐私与安全性"授权；若脚本报权限错误，去"系统设置 → 隐私与安全性 → 文件与文件夹"检查 Docker 授权。
- Git 委派依赖该目录下的 `.gitconfig`（`manager/scripts/setup-host-symlinks.sh` 在容器内 `ln -sf /host-share/.gitconfig /root/.gitconfig`）；若把共享目录改小，请确保 `.gitconfig` 在其内。

### 4.5 大小写与 `.DS_Store`

- APFS 默认大小写不敏感 → 与 Windows 同样的改名陷阱（见 2.4）。
- 仓库 `.gitignore` 已忽略 `.DS_Store`，无需额外配置；但被挂载进容器的目录若含 `.DS_Store`，会被 `shared/lib/worker-file-sync.sh` 一并同步（无功能影响，仅噪音）。
- 仓库里 `docs/zh-cn`、`blog/zh-cn` 等目录名请勿改成 `zh-CN`。

## 五、构建注意事项

### 5.1 make 与 recipe 语义

macOS 自带 GNU make 3.81，`Makefile` 使用的 `$(shell)`、`ifeq`、`$(foreach)`、`$(subst)`、`$(if)`、`$(or)` 均可运行，**通常不必装新的 make**；如遇到 3.81 的古老限制（缺少 `$(file)`、`$(eval ...)` 边界行为），再：

```bash
brew install make   # 之后使用 gmake，避免与 /usr/bin/make 冲突
```

`Makefile` 中的 `VAR=val cmd` 前缀赋值（如 `OUT_DIR=... ruby ...`、`AGENTTEAMS_YOLO=1 $(MAKE) install`）在 macOS 的 bash/sh 下天然可用——这是相比 Windows 的巨大便利。

### 5.2 代理与镜像源

- Docker build 不继承宿主 shell 代理。macOS 上：

  ```bash
  PROXY_ARGS="--build-arg HTTP_PROXY=http://host.docker.internal:1087 \
      --build-arg HTTPS_PROXY=http://host.docker.internal:1087"
  make build-manager DOCKER_BUILD_ARGS="${PROXY_ARGS}"
  ```

  - Docker Desktop → 用 `host.docker.internal`
  - Podman on macOS → 用 `host.containers.internal`（见 `AGENTS.md` 的 Makefile 构建示例）

- 无代理时的国内镜像参数：

  ```bash
  make build-openclaw-base DOCKER_BUILD_ARGS="--build-arg APT_MIRROR=mirrors.aliyun.com --build-arg NPM_REGISTRY=https://registry.npmmirror.com/"
  make build-copaw-worker DOCKER_BUILD_ARGS="--build-arg APT_MIRROR=mirrors.aliyun.com --build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/"
  ```

- 跑测试时 **必须** 设置 `no_proxy`，否则 127.0.0.1 健康检查会走代理返回 503（官方文档专门强调）：

  ```bash
  export no_proxy="localhost,127.0.0.1,::1,local,169.254/16"
  ```

### 5.3 本地基座镜像的成对参数

```bash
make build-manager build-worker \
    OPENCLAW_BASE_IMAGE=agentteams/openclaw-base \
    OPENCLAW_BASE_VERSION=latest
```

遗漏任一个都会去拉远端 registry 的 `:latest`（母文档 M04 已列为常见坑）。

### 5.4 Apple Silicon：架构与多架构构建

| 场景 | 行为 | 适配 |
|---|---|---|
| `make build`（本地开发） | 产出 `linux/arm64` 镜像 | 本机 Docker Desktop 直接可用 |
| 需要 amd64 镜像本地运行 | `make build DOCKER_PLATFORM=linux/amd64` | 走 QEMU 模拟，慢 |
| `make push`（多架构） | buildx `--platform linux/amd64,linux/arm64` | QEMU 构建 amd64 很慢；CI 亦如此（`docker/setup-qemu-action`） |
| 只验证 arm64 | `make push MULTIARCH_PLATFORMS=linux/arm64` | 建议本地用 |
| Podman | `make push` 自动切到 `podman build --platform ... --manifest` 分支 | 由 `IS_PODMAN := $(shell docker version \| grep -qi podman ...)` 检测 |

**构建缓存**：Apple Silicon 上 QEMU 交叉构建几乎无缓存复用价值，建议：

```bash
# 复用同一个 builder，避免每次重建
make buildx-setup
docker buildx ls
```

**Rust（M09）**：`openhuman` 的 cargo 构建在容器内进行，arm64 上原生编译较快；但 `target/` 会占用数 GB，注意 Docker 磁盘镜像大小。

### 5.5 各镜像构建的 macOS 提示

| 目标 | macOS 提示 |
|---|---|
| `make build-openclaw-base` | 最耗时；需 NPM 源或代理；arm64 原生构建无需 QEMU |
| `make build-agentteams-controller` | 需要 `rm -rf` / `cp -r`（macOS 原生支持）；Go 编译在容器内 |
| `make build-manager` / `build-worker` | 注意 5.3 的成对参数 |
| `make build-manager-qwenpaw` / `build-copaw-worker` / `build-hermes-worker` | 纯 Python，宿主无需 Python 版本匹配 |
| `make build-qwenpaw-worker` | 需要 `ruby` 在 PATH（recipe 用 `OUT_DIR=... ruby ...` 前缀赋值）；系统 ruby 2.6 通常够用，报语法错误时 `brew install ruby` |
| `make build-openhuman-worker` | 容器内 `rust:1.93-bookworm`；QEMU 下若指定 amd64 会非常慢 |
| `make build-embedded` | 依赖 controller 镜像 |

### 5.6 不要做的事

- ❌ 用 `sh script.sh` 代替 `bash script.sh`（POSIX 模式会改变语义）。
- ❌ 在 macOS 上直接跑 `shared/lib/render-skills.sh`（需要 `envsubst`，本意只在镜像内执行）。
- ❌ 把 Docker Desktop 的 file sharing 只留仓库目录却把 `AGENTTEAMS_HOST_SHARE_DIR` 指向家目录（挂载会失败）。
- ❌ 依赖 BSD `date -d` / `sort -V` / `xargs -r` 而不安装 GNU coreutils。

### 6.3 macOS 特有的部署差异

1. **Dashboard 可用**（与 Windows 相反）。Bash 安装器默认启用，端口 13000：

   ```bash
   make install-dashboard      # 或 AGENTTEAMS_DASHBOARD=1
   ```

   注意 `Makefile:944-945` 注释："Linux/macOS only (Bash installer). Windows PowerShell installer does not yet include dashboard support."

2. **端口检查用 `lsof`**（官方 local.md 提供的正是 macOS 命令）：

   ```bash
   lsof -nP -iTCP:18080 -sTCP:LISTEN
   lsof -nP -iTCP:18001 -sTCP:LISTEN
   lsof -nP -iTCP:18088 -sTCP:LISTEN
   lsof -nP -iTCP:13000 -sTCP:LISTEN
   ```

3. **外部访问**（`AGENTTEAMS_LOCAL_ONLY=0`）：macOS 应用防火墙可能拦截，首次会弹窗需允许；局域网访问用 `ipconfig getifaddr en0` 取本机 IP，手机端 homeserver 填 `http://<lan-ip>:18080`。

4. **Podman 用户注意**：
   - `podman machine` 必须先启动，否则 socket 不存在；
   - 安装器的 `Podman autostart` 选项依赖 systemd，**macOS 上不会出现**（`local.md` §17）；
   - `make push` 会自动走 manifest 分支；
   - 容器访问宿主用 `host.containers.internal`。

5. **Apple Silicon 的 Higress Console**：走安装脚本会自动注入 `JVM_ARGS`（见 2.5）；若手工启动容器出现 Console 崩溃（SIGILL），检查 `JVM_ARGS` 是否传入。

6. **容器日志**（macOS 路径仍是 Linux 路径）：

   ```bash
   docker logs agentteams-controller
   docker exec agentteams-controller cat /var/log/agentteams/tuwunel.log
   docker exec agentteams-manager cat /var/log/agentteams/manager-agent.log
   ```

7. **卸载**：`make uninstall` 或 `bash install/agentteams-install.sh uninstall`；注意卸载会删除卷、env 文件、日志与 Manager 工作区。

8. **资源导入**：`bash install/agentteams-import.sh worker --name alice --zip ./alice.zip`（Bash 版功能与 PowerShell 版对齐）。

### 6.4 本地 K8s（kind）在 macOS 上

`hack/local-k8s-up.sh` 使用 `uname -m` 推导平台，在 macOS arm64 上会得到 `linux/arm64`（正确）：

```153:153:hack/local-k8s-up.sh
    PLATFORM="linux/$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/')"
```

适配要点：

1. 需先安装 `kind`、`helm`、`kubectl`、`docker`（脚本会做 preflight 检查）。
2. `hack/kind-config.yaml` 把 NodePort `30080` 映射到宿主 `18080`；请确认 18080 未被 AgentTeams 本地安装占用。
3. 脚本会用 `docker save | docker exec <cluster>-control-plane ctr ... images import` 预载镜像（不用 `kind load` 以避免多架构 manifest 问题），在 macOS 上通过 Docker VM 完成，属正常路径。
4. 预载镜像列表包含 higress 系列，国内网络建议先配好代理/加速。
5. 结束后用 `make local-k8s-down`（等价 `bash hack/local-k8s-down.sh`）清理。

| `date: illegal option -- d` | BSD `date` | `brew install coreutils`（用 `gdate` 或 gnubin） |
| `sort: invalid option -- V` | BSD `sort` | `brew install coreutils`（`gsort`） |
| `declare: -A: invalid option` | 系统 bash 3.2 跑 `migrate/skill/scripts/analyze.sh` | `brew install bash` 后用 5.x 执行 |
| Higress Console 崩溃（SIGILL） | Apple Silicon JVM 指令集 | 安装器已自动注入 `JVM_ARGS`；手工启动容器需自己传（2.5） |
| 健康检查 503 | `http_proxy` 捕获了 127.0.0.1 | 设置 `no_proxy`（5.2） |
| 构建时 clone/拉包超时 | 构建容器无代理 | 用 `host.docker.internal` 传 build-arg |
| 容器访问本地模型失败 | 写了 `localhost` | 改用 `host.docker.internal` / `host.containers.internal`（4.3） |
| 挂载目录在容器内看不到 | Docker Desktop file sharing 未包含该目录 | Settings → Resources → File sharing 加入路径 |
| bind mount 读写极慢 | gRPC-FUSE | 启用 VirtioFS；大数据用命名卷（`agentteams-data`） |
| Podman 安装脚本报 socket 不存在 | `podman machine` 未启动 | `podman machine start` |
| 多架构推送极慢 | QEMU 模拟 amd64 | 本地用 `MULTIARCH_PLATFORMS=linux/arm64`，多架构交给 CI |
| `docs/zh-cn` 改名后 CI 报错 | APFS 大小写不敏感导致改名未真正生效 | `git mv` 两步改名 |
| Dashboard 未启动 | 使用了 dry-run/手工流程 | 用 Bash 安装器并确认 `AGENTTEAMS_DASHBOARD=1`、端口 13000 空闲 |

### 8.3 最小可用 macOS 开发闭环

```bash
# 0) 一次性准备
xcode-select --install
brew install coreutils findutils jq kubectl helm kind
export PATH="/opt/homebrew/opt/coreutils/libexec/gnubin:/opt/homebrew/opt/findutils/libexec/gnubin:$PATH"

# 1) 构建（本地 arm64）
make build-manager build-worker \
     OPENCLAW_BASE_IMAGE=agentteams/openclaw-base OPENCLAW_BASE_VERSION=latest

# 2) 安装（embedded，自动处理 Apple Silicon JVM 修复）
AGENTTEAMS_LLM_API_KEY="sk-xxx" make install

# 3) 验证

curl -fsS http://127.0.0.1:18088/ >/dev/null

# 4) 测试（注意 no_proxy）
```
