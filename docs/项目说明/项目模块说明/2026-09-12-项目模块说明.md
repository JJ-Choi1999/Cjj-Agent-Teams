## 一、文档说明

本文档按“一个功能模块 = 一个顶层目录（或一组内聚目录）”的方式组织，每个模块包含四项固定内容：

| 项 | 含义 |
|---|---|
| **目录路径** | 模块在仓库中的相对路径 |
| **文件清单与用途** | 目录/关键文件名称 + 用途说明 |

## 二、项目总览

### 2.1 系统定位

AgentTeams 是一套**基于 IM（Matrix 协议）的多 Agent 协作系统**，采用 `Manager Agent（协调者）+ Worker Agents（执行者）` 的双层结构，并保留 Human-in-the-loop（人类随时介入）。核心链路：

```
Human ──Matrix Room──> Manager Agent ──委派──> Worker Agents
                            │                       │
                            ├── AI Gateway（Higress / 阿里云 APIG）── LLM 与 MCP 工具
                            ├── Matrix Homeserver（Tuwunel）── 通信
                            └── 对象存储（MinIO / OSS）── 配置与状态（Worker 无状态）
```

控制面由 Go 编写的 Kubernetes Operator（`agentteams-controller`）承担，负责将 `Worker / Manager / Team / Human` 四类 CRD 调谐为真实容器、Matrix 用户/房间、网关消费者与存储凭据。生产部署走 `helm/`，本地部署走 `install/`。

### 2.3 运行时矩阵

**Worker 运行时**（由 Worker CR `spec.runtime` 或安装默认值决定）：

| runtime | 技术栈 | 对应仓库目录 |
|---|---|---|
| `openclaw`（默认） | Node.js / OpenClaw | `worker/` + `openclaw-base/` |
| `copaw` | Python / AgentScope | `copaw/` |
| `qwenpaw` | Python / QwenPaw 2.x | `qwenpaw/` |
| `hermes` | Python / hermes-agent | `hermes/` |
| `deepseek-harness` | Node.js / `@deepseek-ai/dsh` | `deepseek-harness/` |
| `openhuman` | Rust / openhuman-core | `openhuman/` |

**Manager 运行时**（环境变量 `AGENTTEAMS_MANAGER_RUNTIME`）：

| runtime | 行为 |
|---|---|
| `openclaw` | OpenClaw gateway；Matrix 主通道使用 **message 工具**模式 |
| `qwenpaw`（默认）/ `copaw`（别名） | Python QwenPaw workspace；Matrix 通道使用 `copaw channels send` CLI |

> Hermes / DeepSeek Harness / OpenHuman 目前仅作为 **Worker** 运行时。

### 2.4 部署形态

部署形态由 `AGENTTEAMS_RUNTIME` 决定，影响 Manager 容器内哪些 bootstrap 步骤执行：

| 形态 | 说明 | 入口 |
|---|---|---|
| `local`（embedded） | 单容器 all-in-one：Tuwunel + MinIO + Higress + Controller + Manager Agent，由 supervisord 编排 | `install/agentteams-install.sh`、`manager/supervisord.conf` |
| `aliyun` | 云上轻量：基础设施外部（SAE + AI Gateway + OSS），Manager 容器只跑 Agent | `manager/docker-legacy/Dockerfile.aliyun` |
| `k8s` | Controller 负责 Matrix 注册与网关配置，Manager 容器不再重复 bootstrap | `helm/agentteams/` |

## 三、功能模块详解

### M01 控制面：agentteams-controller

**目录路径**：`agentteams-controller/`

**模块职责与主要功能**

Go 编写的 Kubernetes Operator，是全系统的控制面。职责：

1. **CRD 定义**：定义并注册 `Worker`、`Team`、`Human`、`Manager` 四类资源。
2. **Reconciler 调谐**：将 CR 期望态调谐为真实资源——容器/Pod、Matrix 用户与房间、Higress 消费者与路由、MinIO 用户与凭据、ServiceAccount。
3. **REST API 服务**：对外暴露统一 HTTP API（声明式资源 CRUD + 命令式生命周期 + 项目/工作流 + AppService 事务）。
4. **`agt` CLI**：供 Manager Agent 与运维人员调用的命令行工具。
5. **嵌入式模式**：在 all-in-one 容器内自举 kube-apiserver（`apiserver`）+ kine/SQLite（`store`）替代真实 etcd。

**文件清单与用途**

```

├── Dockerfile               # 独立镜像：编译 controller + agt；含 mc、kube-apiserver、CRD、agent 模板
```

### M02 Manager Agent：manager

**目录路径**：`manager/`

**模块职责与主要功能**

Manager 镜像与 Agent 定义的唯一来源。包含两条运行时链路（OpenClaw / QwenPaw），以及 Manager、Worker、Team Leader 三类 Agent 的提示词与技能模板。Manager 是系统的“协调者”：接收 Human 指令 → 选择/创建 Worker → 委派任务 → 汇总结果。

**文件清单与用途**

根级：

| 文件 | 用途 |
|---|---|
| `Dockerfile` | OpenClaw 运行时 Manager 镜像（FROM `openclaw-base`；含 mc、`agt`、openclaw-cms-plugin） |
| `Dockerfile.qwenpaw` | QwenPaw 2.0（Python）运行时 Manager 镜像（FROM `python:3.11-slim`，pip 装 `qwenpaw==2.0.1`） |
| `supervisord.conf` | all-in-one 本地栈进程编排（priority 分层：minio→tuwunel→higress 组件→controller→Manager Agent） |
| `README.md` | Manager 容器说明与完整环境变量表 |

`manager/scripts/`：

| 文件 | 用途 |
|---|---|
| `setup-host-symlinks.sh` | 将 `/host-share/.gitconfig` 软链到 `~/.gitconfig`（git 委派） |
| `systemctl-shim.sh` | Docker 内拦截 `systemctl`：`restart openclaw-gateway` → `SIGUSR1` 进程内重启 |
| `init/start-manager-agent.sh` | **统一入口**（最大脚本）：三种部署形态、runtime 选择（qwenpaw/copaw/openclaw）、时区、YOLO 模式、必填校验、Matrix 注册、Higress 消费者、worker/human 初始化 |
| `init/start-qwenpaw-manager.sh` | QwenPaw 2.0 启动：OpenClaw 风格 workspace → QwenPaw 风格转换（`.qwenpaw`、`config.json`、`providers.json`） |
| `init/start-element-web.sh` | 生成 Element Web `config.json` + Nginx 配置，监听 8088 |
| `init/start-tuwunel.sh` | 启动 Tuwunel Matrix Homeserver（`CONDUWUIT_*` 前缀，端口 6167） |

## 五、核心数据流与契约

### 5.1 声明式资源流（CR → 真实资源）

```
用户/Manager 提交 YAML
   │  install/agentteams-apply.sh 或 agt apply 或 REST API
   ▼
agentteams-controller（server/resource_handler.go）
   │  写入 CR（Worker / Team / Human / Manager）
   ▼
Reconciler（internal/controller/*）
   ├─ service/Provisioner      → Matrix 用户、房间、网关消费者、MinIO 用户、SA
   ├─ service/Deployer         → 生成 openclaw.json / AGENTS.md / runtime.yaml 到对象存储
   ├─ backend/(docker|kubernetes|sandbox) → 创建/更新容器或 Pod
   └─ gateway/ + credprovider/ → 绑定模型路由与 STS 凭据
   ▼
Worker 运行时（copaw/qwenpaw/hermes/openclaw/dsh/openhuman）
   │  shared/lib/agentteams-env.sh 引导 + sync 拉取配置
   └─ 以 Matrix 为唯一通信通道
```

### 5.2 运行时配置契约

- `docs/design/member-runtime-config-contract.md`：Controller 写入成员的 YAML 运行时配置（`runtime.yaml`）契约。
- 消费者：`qwenpaw/src/qwenpaw_worker/update.py`（热更新）、`deepseek-harness/scripts/runtime_env.py`（解析 model/gateway）。
- 样例：`plugins/teamharness/adapters/deepseek-harness/fixtures/runtime.yaml`。

### 5.3 TeamHarness 工具契约

- MCP 工具集：`health` / `message` / `roomflow` / `filesync` / `artifact` / `projectflow` / `taskflow`。
- 契约文档：`docs/design/teamharness/boundary-and-contracts.md`；校验：`plugins/tests/teamharness/test-contracts.rb`。
- 角色 prompt：`plugins/teamharness/prompts/{team,agent,manager}/**`。

### 5.4 沟通与存储约定

| 维度 | 约定 |
|---|---|
| 通信 | 全部在 Matrix Room 内（Human + Manager + Worker 同房间），Human 可见可介入 |
| 存储 | 全部 Agent 配置与状态存 MinIO/OSS；Worker 无状态，可随意重建 |
| 凭据 | Worker 用**一个** Consumer key-auth token 同时访问 LLM 与 MCP；由 Manager/Controller 控制权限 |
| 技能 | `SKILL.md` 即自包含文档；OpenClaw 从 `workspace/skills/<name>/SKILL.md` 自动加载 |

## 六、维护须知

1. **Agent 面向内容写作约定**：`manager/agent/**` 下所有文件由 Agent 运行时读取，必须用**第二人称**（“你是 Manager…”“用这个脚本…”），禁止第三人称描述。适用范围：`manager/agent/**`、各 `*-worker-agent/**`、`team-leader-agent/**`、`worker-skills/**`。
2. **CRD 单一事实来源**：只改 `agentteams-controller/config/crd/`，然后 `make sync-crds`；CI 会拦截不同步。
3. **本地构建基础镜像**：必须成对使用 `OPENCLAW_BASE_IMAGE=agentteams/openclaw-base` 与 `OPENCLAW_BASE_VERSION=latest`，否则会拉远端 `:latest`。
4. **文档路径纠正**：根目录**不存在** `design/`；设计文档在 `docs/design/`。`AGENTS.md` 中的 `design/*` 引用为历史遗留。
5. **已知过时描述**：
   - `worker/README.md` 提到的 `worker/agent/skills/` 已迁至 `manager/agent/worker-agent/skills/`。
   - `manager/README.md` 未列全 `scripts/lib/`（实际含 `gateway-api.sh`、`builtin-merge.sh`）。
6. **近似空目录**（勿误判为缺失）：`openclaw-base/`（仅 `Dockerfile`）、`openhuman/`（`Dockerfile` + 1 个 entrypoint）、`worker/`（无源码）。
7. **插件适配器边界**：`plugins/teamharness/adapters/` 仅有 `qwenpaw` / `deepseek-harness` / `claude-code`；`openclaw`、`copaw`、`hermes` 是根目录运行时镜像，不是适配器。
8. **发布策略**：PR 不更新共享 changelog 文件；发布 tag 时由 release workflow 依据 PR 自动生成变更列表。
9. **新增模块时的自检清单**：模块目录 → `Makefile` 目标 → `.github/workflows` → `install/` 选项 → `docs/` → `AGENTS.md` 目录树 → 本文件。
